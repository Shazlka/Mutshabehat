# Hifz training implementation plan

Goal: upgrade the existing /test into an authenticated, entirely MCQ Quran memorization learning loop.
Architecture: pure indexed Quran generators and adaptive/analytics functions; server repository and atomic Postgres scoring; thin API and Arabic UI. Existing Quran JSON and Mushaf metadata remain authoritative. Legacy /test UI preserved at /test/legacy.
Stack: existing Next 16 / React 19 / TypeScript / Supabase Postgres / Tailwind 4, Node test runner; Playwright for browser verification.
Spec: user's complete 64-section Hifz request in this session.

## Audit
- Quran/surah data: public/quran/{ayahs,surah-names}.json; 6236 verses. No Quran SQL table.
- Mushaf: packages/quran-data/mushaf1441/pageMetadata.ts; page, juz, hizb mapping.
- Similar verses: groups -> verses -> parts; automated_groups.payload. Studied means groups.completed.
- User: Supabase auth.users and profiles, automatic login in proxy.ts. Reads under RLS.
- Existing quiz: /test, TestRunner, test-questions{-quran}, /api/test/answers, test_answers. Browser exposes answers and supports flashcards.
- Design: warm paper/indigo tokens, Cairo UI, Amiri Quran, RTL app shell.
- Tests: tsx node:test, Qiraat tests and seven Mushaf validators. Browser suite needs adding.
- Production DDL approval required by HANDOFF. Validate migration in isolated DB; production is a final approval gate.
