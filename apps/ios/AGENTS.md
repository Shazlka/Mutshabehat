# Qiraat iOS app: rules for every agent (Claude, Codex) and person

The native iPhone/iPad app «Qiraat» (`com.shazlka.qiraat`) for the Mushaf 1441 reader and the
القراءات العشر layer. Read this file before touching anything under `apps/ios`.

## 1. Branch and folder policy (user decision, 2026-10-01)

- The iOS app lives on the long-lived branch **`ios/main`**, checked out in its own folder
  **`~/Projects/qiraat-ios`** (a git worktree of the same repo). The web app stays on `main` in
  `~/Projects/mutshabehat-v2`.
- **`ios/main` is never merged into `main`.** A push to `main` deploys the web app to production;
  nothing iOS ever goes there.
- **The web app and its database are the only source of data and improvements.** Data flows one way:
  `main` → `ios/main` (`git merge origin/main`), and the live web API → the app's generated data.
  The iOS app never writes to the web app's database and never changes web code.
- **Every file this branch adds or changes is under `apps/ios/`.** `make check-isolation` fails if
  the branch differs from `origin/main` anywhere else; it runs in `make test`. That is what keeps
  `git merge origin/main` conflict-free.
- Feature work: branch `ios/<topic>` from `ios/main`, merge back into `ios/main`.

## 2. Commands (run from `apps/ios`)

```bash
brew install xcodegen          # once
make test                      # data + fonts + Qiraat data + project, then every test (iPhone simulator)
make test-ipad                 # UI tests on the iPad Pro 13-inch simulator
make perf                      # release-mode page load + layout budget
make run                       # build, install and launch on the iPhone simulator
make open                      # open the generated project in Xcode
make device                    # build, install and launch on a connected iPhone (needs signing, §6)
make qiraat-refresh            # re-download the Qiraat data from the live web app
```

Xcode 27 ships no `Simulator.app`. When iterating on a failing UI test, pass
`-collect-test-diagnostics never` to xcodebuild, or it spends 600 s collecting diagnostics.

## 3. What is committed and what is generated

| Path | What | In git? |
|---|---|---|
| `project.yml` | XcodeGen spec, source of truth for the Xcode project | yes |
| `Mutshabehat.xcodeproj`, `Sources/Info.plist` | generated by `make project` on every run | no |
| `MushafCore/` | Swift package, no UIKit: SQLite reader, QCF fonts, page layout, navigation, Qiraat model | yes |
| `Sources/`, `UITests/` | the app and its XCUITests | yes |
| `scripts/` | data generators and their tests (Python stdlib only) | yes |
| `Generated/mushaf.sqlite` | built from `packages/quran-data/mushaf1441/fixtures` (the web's data) | no |
| `Generated/Fonts/p1…p604.woff2` | QCF V2 fonts from the CDN the web uses | no (licence) |
| `Generated/qiraat/page-NNN.json` | snapshot of the live web API `/api/mushaf-1441/qiraat?page=N` | no |
| `Config.xcconfig`, `Signing.xcconfig` | Supabase anon key; signing team | no |

The repository is public: never commit keys, data or fonts.

## 4. Rules carried over from the web reader (do not break)

- Page geometry is a port of `Mushaf1441Viewer.tsx` (`MushafCore/.../PageLayout.swift`). Change both or neither.
- Surah header / basmala slots match `pageDecorations.ts` exactly (0 differences across 604 pages).
- A page's glyphs render only in that page's font. Never fall back to another page's font.
- Draw and measure every token as a CoreText line (`QCFFontStore.line` / `advance`): 198 tokens are
  rub al-hizb ۞ + a word joined by a space, and the QCF fonts have no space glyph.
- CoreText draws QCF glyphs left to right (Private Use Area, no bidi class): `PageLayout` places words itself.
- Page curl: spine on the right, UIKit's "before" page is the NEXT page; a spread is `[right+1, right]`.
- Resume key `mushaf1441:last-page:v1`, clamped to 1–604.
- Qiraat: show only what the web shows. Colours, reader/narrator names and the rule "a press is
  answered only by the active layer" come from the web (`packages/qiraat-core`, `PROJECT_MASTER.md` §13).
  Never write a bare «خلف» or «الدوري»: always the disambiguated name the data carries.

## 5. Process

- Every change gets a dated entry, newest first, in **`apps/ios/CHANGELOG.md`** (not the root
  changelog, which belongs to the web app).
- Tests first: Swift Testing in `MushafCore`, XCTest/XCUITest for the app, `unittest` for scripts.
- Commits: author `Shazlka <amr.eshazly@gmail.com>`; no model names in commits, PRs or code comments.
- Never sign in, enter credentials, or push without the user's go-ahead.

## 6. Running on the user's iPhone

The user adds Apple ID `amr.eshazly@icloud.com` in Xcode → Settings → Accounts (an agent never does),
connects the iPhone, trusts the Mac, and turns on Settings → Privacy & Security → Developer Mode.
`make device` then finds the personal team, writes it to the gitignored `Signing.xcconfig`, builds with
automatic signing and installs. A free personal team's install expires after 7 days; re-run `make device`.
