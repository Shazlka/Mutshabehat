## 2. App Review notes (English, paste into "Notes")

```
WHAT THE APP IS
Qiraat is a Quran reader in the Madinah 1441 mushaf page layout. Its purpose is the ten canonical readings of the Quran (al-Qira'at al-'Ashr): on every page it marks the words where the ten readers and their twenty narrators (riwayat) read differently, and explains each reading and who reads it. It also has a similar-verses tool (mutashabihat), memorization tracking and bookmarks. The interface is Arabic by default; English is available (step 1). The Quran text itself is always Arabic.

NO LOGIN
There are no accounts, no sign-in, no purchases and no ads. Every feature is available on first launch.

5 STEPS TO SEE THE MAIN FEATURES
Tip: the bars hide while reading. Tap the page margin (not a word) to show them.
1. Bottom bar, gear icon "Settings" (الإعدادات) > Language (اللغة) > English. Tap Done.
2. Bottom bar, "Qira'at" (القراءات) > turn the layer on. Words that differ between the readings are now coloured on the page. Page 1 (Al-Fatihah) and pages 2 to 5 are good examples.
3. Tap a coloured word, for example "maliki" in verse 4 of Al-Fatihah on page 1. A card lists each reading of that word and the readers/narrators who read it. Swipe within the card to move to the next variant on the page.
4. Open the "Qira'at" menu again and choose a reader or narrator filter (for example Warsh). The page now shows only where that narrator differs from Hafs. The same menu has the colour key, the page summary, search in the readings and the usul index.
5. Bottom bar, "More" (المزيد) > "Mutashabihat" (similar verses with their differences highlighted), "Memorization", and "Mutoon" (the classical poems that document the readings).
On iPad, rotate to landscape for the two-page spread; Settings > Landscape view > Learning shows one page with a side bar of readings.

OFFLINE BEHAVIOUR
All 604 pages, their fonts, the Quran database and a full snapshot of the readings data are inside the app, so everything works in Airplane Mode. When the device is online, the app quietly checks a public, read-only endpoint for newer readings data and replaces a page only after validating the response. If that check fails, the app keeps showing the bundled data and shows no error.

WHY THIS IS NOT A DUPLICATE OF OTHER QURAN APPS (Guideline 4.3)
General Quran apps show one narration (usually Hafs). This app's core is a word-level layer for the ten canonical readings: each differing word carries its readings, the reader and narrator who read each one (20 riwayat), whether it is a farsh or an usul difference, filtering by any one narrator, side-by-side comparison of two narrations, an usul index, and the mutoon verses that document the reading. The Madinah layout is drawn natively from per-page fonts so that the readings can be marked on the exact printed word. This is our only Quran app; it is not built from a template or shared code base with other listings.

DATA AND PRIVACY
No data leaves the device except the anonymous read-only request for readings updates. No analytics, no tracking, no third-party SDKs. Backups are written only to a folder the user picks in the Files picker.

Contact during review: <owner email>, <phone>
```

## 4. App Privacy ("nutrition label")

Apple's rule: "Data that is processed only on device is not 'collected' and does not need to be disclosed."
"Collect" means sending data off the device and keeping it readable longer than needed to serve the
request; an IP address or token sent with a request and not retained need not be disclosed. Source:
[App privacy details](https://developer.apple.com/app-store/app-privacy-details/).

### 4.1 Assumption this answer depends on

The live-update endpoint the Release app calls will be:
1. **cookie-less**: it never sets or reads a session cookie, and the app's request does not keep cookies
   (use an ephemeral `URLSession` or `httpShouldHandleCookies = false`);
2. **read-only and anonymous**: GET only, no user id, device id or install id in the request. The current
   request sends only `page=N` and the fixed User-Agent `Qiraat-iOS-Live`;
3. **not logging identifiable requests**, or the logs are short-lived operational logs not used for any
   purpose (no analytics, no linking to a person).

Today the endpoint fails assumption 1. The production web app signs every visitor in as the owner
(`src/proxy.ts`), and `QiraatLiveSync.fetchFromWeb` uses `URLSession.shared`, which keeps that cookie.
See section 8, item F1.

### 4.2 Answer: "Do you or your third-party partners collect data from this app?" → **No, we do not collect data from this app**

Per data type (all **Not collected**):

| Category | Data type(s) | Collected? | Why |
|---|---|---|---|
| Contact Info | Name, Email, Phone, Address, Other | No | no accounts, no forms. "Report an error" uses the system share sheet; the user chooses the recipient. If they email the developer, that is ordinary email, outside the app |
| Health & Fitness | Health, Fitness | No | reading/memorization progress is not health data, and stays on device |
| Financial Info | all | No | free, no purchases |
| Location | Precise, Coarse | No | no Core Location; IP not retained (assumption 4.1.3) |
| Sensitive Info | Sensitive Info | No | religious practice could count as sensitive, but nothing about the user's practice leaves the device |
| Contacts | Contacts | No | not accessed |
| User Content | Emails/Texts, Photos/Videos, Audio, Gameplay, Customer Support, Other User Content | No | notes, bookmarks, personal groups and memorization are stored in local SQLite. Backups go to a folder the user picks (their own iCloud Drive or device); the developer cannot access it |
| Browsing History | Browsing History | No | |
| Search History | Search History | No | Quran and readings search run on device against bundled SQLite |
| Identifiers | User ID, Device ID | No | no user id, no IDFA, no IDFV sent. The per-install device id exists only in the DEBUG review editor |
| Purchases | Purchase History | No | |

Tracking: **No**. `NSPrivacyTracking = false`, `NSPrivacyTrackingDomains` empty, no App Tracking

### 4.3 What changes if the assumption does not hold

| If… | Then the label must change to… | Better fix |
|---|---|---|
| the endpoint keeps setting a session cookie (owner session) | a privacy label cannot fix this. Every install holds write-capable owner credentials. **Do not ship** | cookie-less public read endpoint or a static CDN snapshot; re-lock editor RPCs (F1) |
| the server creates a per-install session or anonymous user | **Identifiers → User ID** (or Device ID), *linked to user: No* (no identity), purpose **App Functionality** | don't create sessions for public reads |
| Vercel / Caddy logs with IP + path are retained and readable (e.g. Vercel log drains, Caddy access logs on the Mac Mini) | Apple says to declare by use: **Coarse Location** or **Diagnostics → Other Diagnostic Data**, plus possibly **Usage Data → Other Usage Data**; *not linked*, *not tracking*, purpose **App Functionality** | turn off access logs for the read endpoint, or drop IPs; keep logs only as long as needed to serve the request |
| "Fetch Directly from Web App" (`syncDirectlyFromWeb`, `api/groups/export`) ships | the app downloads the owner's personal groups to every user. That is the owner's data being disclosed, and it fails without the cookie. Remove it rather than label it | remove from Release (F4) |
| a crash/analytics SDK is added later (Sentry, Firebase, etc.) | **Diagnostics → Crash Data / Performance Data**, plus whatever the SDK collects; update the privacy manifest | keep v1 SDK-free |
| a feedback form posting to a server is added | **Contact Info → Email** and **User Content → Customer Support**, linked to user | keep the share-sheet approach |

## 7. EU DSA trader status and territories

### 7.1 Trader status (owner decides; Apple cannot decide for you)

Source: [Manage EU DSA trader requirements](https://developer.apple.com/help/app-store-connect/manage-compliance-information/manage-european-union-digital-services-act-trader-requirements).

- You are asked when you submit a new app. Account Holder or Admin sets it in Business.
- **Non-trader** ("This is not a trader account"): no contact details needed. EU users are told EU
  consumer-protection rights don't apply to contracts with you. This fits an individual publishing a free
  app with no income from it. If you might monetize later or publish as a business, reconsider.
- **Trader**: for an individual, you must provide an address (or P.O. Box), a phone number and an email.
  Phone and email are verified by code, and you upload a document proving name and address. **These appear
  publicly on the EU product page.** You also certify compliance with EU law.
- From general knowledge, not from the page above: since February 2025 Apple removes apps from the 27 EU
  storefronts when the account has not declared a status. Declare before release either way.

### 7.2 Territories checklist

| Decision | Recommendation |
|---|---|
| Default | All territories except those below. Free app, no payments, no local-law features |
| **China mainland** | **Exclude.** New apps need an ICP filing number, and Quran apps were removed from the China store in 2021 at the government's request |
| EU (27) | Include only after the DSA status is declared |
| South Korea | 4+ is fine; Korea may issue its own rating (GRAC). If it does, a new version with the RCN is required |
| Brazil, Australia | regional age ratings derive from the questionnaire; nothing extra for a 4+ app |
| Russia, Belarus, Iran, others under sanctions | Apple controls availability; nothing to do |
| Pre-orders | Off |
| Release | **Manual release** after approval, so you can check the live listing first |
