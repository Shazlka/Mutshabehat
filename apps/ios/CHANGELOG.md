# Qiraat iOS app — changelog

> Newest first. One dated entry per change. iOS changes are logged here, never in the root
> `CHANGELOG.md`, which belongs to the web app (see `AGENTS.md` §1).

## [Unreleased] — 2026-10-13 — Reading sync and backup integrity repairs
- Reading data now publishes a separate snapshot per device and merges all available snapshots before publishing; a late upload can no longer replace another device's file. The old root `reading.sqlite` remains readable for migration.
- Bookmark and surah removals now carry deletion records. Reading activity carries identified events, so distinct sessions add across devices without counting the same event twice. SQLite merge operations fail and roll back on errors; sync reports failures instead of marking a failed reading merge as successful.
- Backup history refers to immutable, content-addressed Qiraat archives. Restore resolves the archive named by each snapshot manifest, and retention removes archives after no retained snapshot refers to them. Failed Qiraat imports preserve the existing live-page overlay.
- Bookmark edits schedule cloud sync. Generated `MushafCore/build` output is excluded from Git.
- Added database, backup-history and two-device simulator regression tests. Physical iCloud Drive acceptance is still required.

## [Unreleased] — 2026-10-11 — Qiraat features and UX round (branch `ios/qiraat-ux`)
The per-workstream entries of this round are in [CHANGELOG-archive.md](CHANGELOG-archive.md).
- **Reader top bar:** five 44 pt icons (search, bookmarks, Qiraat menu, «المزيد», settings). The Qiraat menu holds the layer switch, the reader/narrator filter, the colour key, the page summary, Qiraat search and the usul index. A filter chip in the reading header shows an active filter without moving the page.
- **New screens:** colour key «مفتاح الألوان»; page summary grouped by ayah; offline Qiraat search (reader/narrator, word, باب) over all 604 pages; usul index (23 categories, 12,506 rulings, 12,297 places); side-by-side compare of two readers or narrators at a word.
- **Word sheet:** previous/next marked word without closing, numbered variant faces, live-sync status chip, «بلّغ عن خطأ» link, favourites and personal notes (kept in backup and restore; restore merges by `updatedAt` and never deletes local notes), first-use hint, adaptive colours, text-size cap, non-colour cues. The reader picker is a searchable half sheet.
- **Localization:** the Qiraat chrome is translated to English (~170 strings, all marked `needs_review`); Quran text, reader and narrator names and ruling data stay Arabic. New `appLocalized` so the app language, not the device language, decides.
- **Verification (final gate, `ios/qiraat-ux`):** isolation check ok; data tests ok; `MushafCore` 433 tests in 45 suites passed; `MutshabehatTests` 260 passed; Release build succeeded and `release_guard` ok; full UI suite 105 tests on iPhone (360 test cases passed in the log, 4 iPad-only tests skipped) and on iPad (105 tests). The full runs had 1 failure on iPhone and 2 on iPad: `testQiraatReaderPickerOpensFullScreenWithColoredReaders` (the test still expected the old label «نافع (روايتاه)»; fixed, passes on both devices) and `testLegendOpensListsReaderRowsAndCloses` on iPad only (scrolling under load; passes alone on both devices, so it is timing-sensitive).
- **Known data gaps (web database, not changed here):** 5 rulings filed under page 1 belong to pages 3, 4 and 7; 2 rulings at 2:33 word 16 have an empty `baseText`; 93 loci carry several ruling rows for one place (the app aggregates them).
- **Not verified:** VoiceOver by hand, real-device haptics, iCloud. English text has not been reviewed by a person. In the dark theme the page still draws the raw Qiraat colours (as before this round). The English navigator shows Arabic-Indic digits and its previous/next follow the reading direction, by design.
- **Repository note:** `MushafCore/build/` is now git-ignored and its 138 tracked build files were removed from the tree; they remain in earlier local history (commit `d341eb0a` on the memorization branch).

## [Unreleased] — 2026-10-10 — The memorization mark no longer sits on the surah name in the top banner
- **Owner report:** on every page the memorization status mark overlapped the surah name while the top banner was showing.
- **Cause:** the mark was an overlay floating over the banner, not part of its layout. With the controls showing it was placed a fixed distance past the icons, right on top of the index button's surah name and page details (measured on iPhone 18 Pro, page 4: mark at x 234–282, page details from x 244); with the reading header showing it sat in the middle whatever the length of the surah name or the juz/hizb text.
- **Fix (`ReaderTopBar.swift`):** the mark now takes its own place in each row: between the surah name and the juz/hizb text in the reading header, and between the index button and the icons with the controls showing (compact there). The texts truncate or shrink to make room instead of running under it. The icon-width offset (`TopBarMetrics.iconGroupWidth`) is gone.
- **Test:** new `testMarkNeverCoversTheBannerText` (the mark's frame never meets the surah name, page details or juz/hizb text, in both states); failed before the fix on the page details.
- **Test fix (no app change):** `ReviewBulkUITests.testFirstWordShowsSuggestionAndAddButton` assumed one swipe lifts the word sheet off its half detent; on a loaded machine it did not, the card low in the lazy list was never built, and the test failed. It now drags the list until the card exists.
- **Verification:** final full runs with these changes: iPhone 18 Pro 278 passed, 1 failed; iPad Pro 13-inch (M5) 281 passed, 2 failed. The three failures (`testStreakIsOneAfterAnUpdateAndZeroAfterUndo`, `testWholeQuranApplyIsFast`, `testHistoryListsBatchAndUndoes`) ran while another session's builds pushed the load average to 100–760; each passes when re-run alone on a quiet machine (the speed test in 0.17 s). `testMarkNeverCoversTheBannerText` and `testFirstWordShowsSuggestionAndAddButton` passed in both full runs. Not verified by hand on a device.

## [Unreleased] — 2026-10-10 — The 7 UI tests that failed before the design-audit work fixed
- **App fix: a long press between words, or low in a line, found no ayah.** The page spreads its 15 lines over the screen, so a line is about twice as tall as its glyphs, and `MushafPageView.ayahKey(at:)` only matched the glyph boxes (plus a few points). A press in the lower half of a line, or in the gap between two words, did nothing, which is why `testRangeAcrossTwoAyatOpensTheUpdateSheetPreselected` could not end its range. A press anywhere in a line of words now answers like a press on the nearest word; surah headers and basmala lines still answer nothing, and ayah-end markers keep their priority. New `MushafPageHitTestTests` (3 tests, failing before the fix).
- **Test isolation: reading progress leaked between UI tests (and into the Mac's iCloud Drive).** The index opens a surah at its first unread page, so `testIndexJumpsToASurah` passed or failed depending on what earlier tests had read. Worse, in the simulator the reading sync falls back to the Mac's own `~/Library/Mobile Documents/com~apple~CloudDocs/Mushaf_Qiraat`, so every test launch merged with, and pushed to, that folder. New DEBUG-only launch argument `-reading-fresh`: a throw-away reading database and no sync folder. `ReaderUITests` launch with it; the real `reading.sqlite` there was verified untouched across a full reader UI run.
- **Test fixes (no app change):** `testSettingCurrentPositionShowsOnDashboard` scrolls its switch above the summary-and-save bar before tapping (on the 6.3" iPhone it starts behind it); the review editor's `reveal` helper scrolls until the whole button is clear of the home indicator (`testAnImalahFaceIsBuiltWithThePresetAndSaved` tapped a button whose centre was off screen); on iPad the settings sheet is short and its list only creates visible rows, so the three settings tests scroll to their row with a new `settingsRow` helper.
- **Verification:** all 7 pass on both devices in the final full runs (counts and the 3 load-related failures in the entry above); `MushafPageHitTestTests` 3/3. The Mac's real `Mushaf_Qiraat/reading.sqlite` kept its size and modification time across a full reader UI run. **Not yet addressed:** UI tests other than `ReaderUITests` do not pass `-backup-folder none`, so a memorization backup in the simulator may still write to the real `Mushaf_Qiraat/Backups` folder.
